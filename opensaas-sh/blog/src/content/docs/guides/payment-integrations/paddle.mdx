### Sandbox and Production Mode

Paddle features two separate environments:
- [Sandbox](https://sandbox-vendors.paddle.com).
- [Production](https://vendors.paddle.com).

They are fully isolated from each other, which means that you need to create separate accounts for each of them. They also feature independent products, prices, API keys, etc.

For local development and testing, you'll want to use Paddle's sandbox mode.
To enable sandbox mode, make sure that `PADDLE_SANDBOX_MODE` is set to `true` in your `.env.server` file, and `REACT_APP_PADDLE_SANDBOX_MODE` is set to `true` in your `.env.client` file:

```ini title=".env.server"
PADDLE_SANDBOX_MODE=true
```

```ini title=".env.client"
REACT_APP_PADDLE_SANDBOX_MODE=true
```

When you're ready to [deploy your app](/guides/deploying/), we'll remind you to set these to `false`.

### Paddle API Key

Once you've created your account, you'll need to get your API key.
You can do that by:
1. Navigating to the `Developer Tools > Authentication` page.
2. Click on the `New API key` button to create a new key.
3. Give your key a name (e.g., "Open SaaS Development").
4. Select the following permissions:
   - `Customers`: read and write
   - `Transactions`: read and write
   - `Customer portal sessions`: write
   - `Reports`: read
   - `Metrics`: read
5. Copy the generated key and add it to your `.env.server` file:
   ```ini title=".env.server"
   PADDLE_API_KEY=pdl_sdbx_apikey_...
   ```

### Paddle Client-side Token

Paddle's checkout runs in the browser with [Paddle.js](https://developer.paddle.com/paddle-js), which needs a client-side token.
You can get one by:
1. Navigating to the `Developer Tools > Authentication` page.
2. Selecting the `Client-side tokens` tab.
3. Click on the `New client-side token` button to create a new token.
4. Copy the generated token and add it to your `.env.client` file:
   ```ini title=".env.client"
   REACT_APP_PADDLE_CLIENT_TOKEN=test_...
   ```

### In-Page Checkout

Unlike the other payment processors, which redirect to a hosted checkout page, Paddle opens its checkout as an overlay in your app.
To enable it, set `openInPageCheckout` to `openPaddleCheckout` in your `src/payment/inPageCheckout.ts` file:

```ts title="src/payment/inPageCheckout.ts"
import { openPaddleCheckout } from "./paddle/inPageCheckout";

export const openInPageCheckout: OpenInPageCheckout | null = openPaddleCheckout;
```

### Default Payment Link

Paddle requires a [default payment link](https://developer.paddle.com/build/transactions/default-payment-link) before it can open a checkout.
To set it:
1. Navigate to the `Checkout > Checkout settings` page.
2. Set the `Default payment link` to `http://localhost:3000`.
3. Click `Save`.

### Creating Products

To create Paddle products, in your Paddle dashboard:
1. Navigate to the `Catalog > Products` page.
2. Click on the `+ New product` button to create a new product.
3. Fill in the product details and click `Save`.
4. On the product page, click on the `+ New price` button.
   - For subscription products, select a `Recurring` billing period (e.g. monthly).
   - For one-time payment products, select `One-time`.
5. Copy the `Price ID` (it starts with `pri_`). Note that Open SaaS uses the price ID, not the product ID.
6. Add the `Price ID` to your `.env.server` file.
   Open SaaS by default expects three products, two subscriptions and one one-time purchase plan:
   ```ini title=".env.server"
   PAYMENTS_HOBBY_SUBSCRIPTION_PLAN_ID=<your-hobby-price-id>
   PAYMENTS_PRO_SUBSCRIPTION_PLAN_ID=<your-pro-price-id>
   PAYMENTS_CREDITS_10_PLAN_ID=<your-credits-price-id>
   ```

:::note[Naming products differently]
Note that if you change names of your products, you'll need to update your app code in `src/payment/plans.ts` and `src/payment/paymentProcessorPlans.ts` to match these names as well.
:::

### Using Paddle Webhook in Local Development

#### Exposing your Webhook Endpoint to the Internet

Paddle notifies your Wasp app about customer and payment events through a webhook. However, to make it available to Paddle during development, you need to expose your locally running Wasp server (started with `wasp start`) to the internet.

You can do that by running `ngrok` on port 3001 (Wasp server runs on port 3001 by default). `ngrok` will then generate a public URL that we can provide to Paddle:

1. First, make sure you have installed [`ngrok`](https://ngrok.com/docs/getting-started/).
2. Once `ngrok` is installed and your Wasp app is running, run:
   ```sh
   ngrok http 3001
   ```
   <Image src={ngrok} alt="ngrok" loading="lazy" />
3. `ngrok` will display a forwarding address. Copy this address and append `/payments-webhook` to it. It should look something like this:
   ```sh title="Callback URL"
   https://89e5-2003-c7-153c-72a5-f837.ngrok-free.app/payments-webhook
   ```

#### Creating your Paddle Webhook

Next, configure the webhook in your Paddle dashboard:
1. Navigate to the `Developer Tools > Notifications` page.
2. Click the `+ New destination` button.
3. Set the `Type` to `Webhook`.
4. In the URL field, paste your `ngrok` forwarding address with `/payments-webhook` appended (for example: `https://abc123.ngrok-free.app/payments-webhook`).
5. Select the following events to listen for:
   - `transaction.completed`
   - `subscription.updated`
   - `subscription.canceled`
6. Click `Save destination`.
7. Copy the destination's secret key and add it to your `.env.server` file:
   ```ini title=".env.server"
   PADDLE_WEBHOOK_SECRET=pdl_ntfset_...
   ```

### Testing Payments in Local Development

Before testing payments, make sure that you created and set all the required env variables in `.env.server` (`PADDLE_API_KEY`, `<NAME>_PLAN_ID` and `PADDLE_WEBHOOK_SECRET`) and `.env.client` (`REACT_APP_PADDLE_CLIENT_TOKEN`), and that your `ngrok` tunnel is running.

You can then test the payment flow:

1. Click a `Buy` button for any product on the homepage.
2. Paddle's checkout should open as an overlay on the page.
3. Fill in the checkout form with [test payment information](https://developer.paddle.com/sdks/sandbox).
4. Complete the payment.
5. You should be redirected to the checkout success page.

To verify everything executed correctly you can:
- Check Paddle webhook event logs:
  1. Navigate to the `Developer Tools > Notifications` page.
  2. Open your previously created destination.
  3. Confirm all of the events have been delivered successfully.
- Inspect your database's `User` table:
  1. Run Wasp DB studio:
     ```sh
     wasp db studio
     ```
  2. Navigate to `localhost:5555` and check the `User` table.
  3. Confirm the `subscriptionStatus` is `active` for the user who made the purchase.
